# 개발자용 Codex 플러그인 설치 안내

지원 범위는 Windows 11, 현재 안정 버전 Codex 데스크톱 앱, Chrome 또는 Edge다. AISideQuest 저장소와 로컬 서버를 직접 실행하는 개발자를 기본 대상으로 한다.

## 연결 전 준비

프로젝트 루트에서 다음 명령을 실행하고 터미널을 열어 둔다.

```powershell
npm.cmd run dev:local
```

`AISideQuest 로컬 환경이 준비되었습니다.`가 표시되고 `http://localhost:5173`에 접속되는지 확인한다. 최초 환경 구성은 [개발 및 실행 가이드](./개발_실행_가이드.md)를 따른다.

## 설치와 연결

1. AISideQuest 저장소를 Codex에서 workspace로 연다. Plugins의 `Personal` marketplace에서 `aisidequest`를 설치하고 활성화한다.
2. hook 신뢰 화면에서 plugin 이름, 이벤트명, `plugins/aisidequest/hooks/` 아래 명령인지 확인한 뒤 승인한다. 다른 경로나 관리자 권한을 요구하면 취소한다.
3. Codex에 `AISideQuest 연결해줘`라고 요청한다.
4. 브라우저가 자동으로 열리면 AISideQuest에 GitHub로 로그인하고, 표시된 기기 이름과 plugin version을 확인한 뒤 **이 기기 연결 승인**을 누른다.
5. Codex가 연결과 테스트 이벤트 성공을 알리면 웹 Devices에 기기가 표시되는지 확인한다. 짧은 Codex 요청을 한 번 실행하고 5초 안팎에 AI 세션이 보이는지 확인한다.

세션 카드에는 전체 경로가 아닌 마지막 프로젝트 폴더명과 최근 명령의 안전한 분류만 표시된다. 예를 들어 `C:\Users\user\IdeaProjects\AISideQuest`와 인자가 붙은 테스트 명령은 각각 `AISideQuest`, `npm test`로 표시된다. 상위 경로, 원본 명령·인자, 환경변수와 도구 결과는 전송하지 않는다.

연결 코드 복사, PowerShell 실행, `device.json` 수동 복사는 필요하지 않다. 플러그인은 원문 기기 token과 verifier를 서버에 보내지 않고 각각 token hash와 S256 challenge만 보낸다. 연결이 승인된 뒤 기기 인증 정보는 사용자 로컬 기본 위치에 한 번만 저장된다.

hook의 queue와 진단 파일은 Codex의 plugin data directory에 저장되지만, 기기 인증 정보는 사용자 로컬 기본 위치를 항상 먼저 사용한다. 과거 플러그인 버전의 plugin data directory에 오래된 `device.json`이 남아 있어도 최신 연결 정보를 가리지 않는다.

## 장애와 복구

- 브라우저 승인 요청은 10분 후 만료된다. 만료되면 Codex에 같은 연결 요청을 다시 말해 새 요청으로 진행한다.
- `API에 연결할 수 없습니다` 또는 `승인 웹에 연결할 수 없습니다`가 나오면 프로젝트 루트에서 `npm.cmd run dev:local`이 계속 실행 중인지 확인한다.
- 브라우저를 자동으로 열 수 없는 환경에서만 웹 Devices의 **복구용 연결 코드**와 bundle 안내의 수동 명령을 사용한다. 연결 코드는 지원 담당자에게 보내지 않는다.
- 서버 또는 네트워크 장애 중에도 event는 사용자 로컬 durable queue에 남고 Codex 작업은 계속된다.
- 플러그인 업데이트 시 지원하는 이전 queue 형식은 자동 변환된다. 업데이트 직후 `deadLetterCount`가 갑자기 증가하면서 자동 감지가 누락되면 이전 형식이 손상으로 오판된 호환성 문제일 수 있으므로, 재연결만 반복하지 말고 plugin version과 발생 시각으로 회귀 여부를 확인한다.
- Codex plugin data directory의 `delivery-diagnostic.json`에서 `status`, `queueDepth`, `oldestAgeMs`, `deadLetterCount`, `updatedAt`, `lastErrorCode`, `lastDeliveredAt`만 확인한다. `READY`로 복구되면 과거 `lastErrorCode`는 제거되고 `updatedAt`은 최신 진단 기록 시각으로 바뀐다. `device.json`, queue, dead-letter 원문은 token 또는 식별 정보가 있을 수 있으므로 보내지 않는다.
- `401` 또는 `403`으로 재연결 안내가 나오면 웹에서 기존 기기를 폐기하고 Codex에 `AISideQuest 다시 연결해줘`라고 요청한다.
- 자동 감지가 보이지 않으면 웹 수동 시작·종료를 사용하고 발생 시각과 앱·plugin version만 확인한다. prompt나 코드를 공유하지 않는다.

## 해제와 삭제

1. 웹 Devices에서 기기를 폐기한다.
2. Codex에서 `aisidequest` plugin을 비활성화·제거한다.
3. plugin data directory의 `device.json`, queue, dead-letter를 사용자 본인이 삭제한다. 서버는 로컬 파일을 원격 삭제할 수 없다.
4. 서버 데이터 사본은 계정의 내보내기 기능으로 받고, 전체 삭제는 최근 재인증 후 계정 삭제를 실행한다.
