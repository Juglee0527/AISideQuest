# 개발 및 실행 가이드

## 준비 사항

- Windows 11 또는 동등한 개발 환경
- Node.js 22.12 이상, 25 미만
- npm
- Docker Desktop
- GitHub 로그인을 시험하려면 GitHub OAuth App

AISideQuest의 기본 사용 방식은 개발자가 이 저장소를 자신의 PC에서 실행하는 것입니다. 별도 도메인이나 유료 서버는 필요하지 않습니다.

## 1. 의존성 설치

프로젝트 루트에서 실행합니다.

```powershell
npm.cmd ci
```

## 2. 환경 변수 준비

`.env.example`을 `.env`로 복사하고 로컬 값을 입력합니다. `.env`는 Git에 올리지 않습니다.

중요한 값:

| 변수 | 로컬 기본 의미 |
|---|---|
| `DATABASE_URL` | PostgreSQL 연결 주소 |
| `CORS_ORIGIN` | 브라우저 주소, 기본 `http://localhost:5173` |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | GitHub OAuth App 자격증명 |
| `GITHUB_CALLBACK_URL` | `/api/v1/auth/github/callback`을 포함한 정확한 callback |
| `VITE_API_BASE_URL` | 프런트엔드가 호출할 API 주소 |

## 3. 로컬 환경 통합 실행

```powershell
npm.cmd run dev:local
```

이 명령은 다음 작업을 순서대로 처리합니다.

1. Docker PostgreSQL 시작
2. server build와 migration 적용
3. 개발 퀘스트 5개 seed
4. API와 웹 동시 실행
5. 두 서비스의 준비 상태 확인

3000 또는 5173 포트가 이미 사용 중이면 다른 포트로 조용히 우회하지 않고 기존 AISideQuest 실행 창을 확인하라는 오류를 표시합니다.

준비가 끝나면 브라우저에서 `http://localhost:5173`에 접속합니다. 실행 터미널은 사용하는 동안 열어 두고 종료할 때 `Ctrl+C`를 누릅니다. PostgreSQL 데이터는 Docker volume에 유지되며 컨테이너까지 중지하려면 나중에 `npm.cmd run db:down`을 실행합니다.

## 4. Codex 플러그인 연결

로컬 환경이 실행 중일 때 Codex에 다음과 같이 요청합니다.

```text
AISideQuest 연결해줘
```

자동으로 열린 브라우저에서 GitHub 로그인 후 **이 기기 연결 승인**을 누릅니다. 연결 코드 복사나 추가 PowerShell 명령은 필요하지 않습니다. API 또는 웹이 꺼져 있으면 플러그인이 `npm.cmd run dev:local` 실행 안내를 표시합니다.

## 5. 개별 실행 명령

통합 실행에 문제가 있을 때만 다음 명령으로 단계를 나눠 확인합니다.

```powershell
npm.cmd run db:up
npm.cmd run db:setup
npm.cmd run dev:server
```

웹은 별도 터미널에서 실행합니다.

```powershell
npm.cmd run dev
```

확인 주소:

- API: `http://localhost:3000/api/v1`
- liveness: `http://localhost:3000/api/v1/health/live`
- readiness: `http://localhost:3000/api/v1/health/ready`
- 웹: `http://localhost:5173`

## 자주 쓰는 명령

| 목적 | 명령 |
|---|---|
| 로컬 통합 실행 | `npm.cmd run dev:local` |
| 로컬 DB 컨테이너 중지 | `npm.cmd run db:down` |
| lint | `npm.cmd run lint` |
| 문서 링크·파일명 검사 | `npm.cmd run docs:check` |
| 타입 검사 | `npm.cmd run typecheck` |
| 기본 테스트 | `npm.cmd test` |
| PostgreSQL 통합 테스트 | `npm.cmd run test:database` |
| production build | `npm.cmd run build` |
| migration 목록 | `npm.cmd run db:show` |
| 브라우저 핵심 흐름 | `npm.cmd run test:e2e` |

PostgreSQL 통합 테스트는 이름에 `test`가 들어간 전용 DB만 사용합니다.

```powershell
$env:TEST_DATABASE_URL='postgresql://aisidequest:aisidequest@127.0.0.1:54329/aisidequest_test'
$env:ALLOW_DATABASE_RESET='true'
npm.cmd run test:database
```

## 코드 작업 원칙

1. 기능을 바꾸기 전에 [`ai/README.md`](./ai/README.md)의 읽기 순서를 확인합니다.
2. DB 변경은 새 migration으로 작성합니다. 이미 적용된 migration을 임의로 고치지 않습니다.
3. API 동작을 바꾸면 테스트와 AI용 계약 문서를 함께 고칩니다.
4. 사용자 흐름이 달라지면 이 폴더의 한글 문서도 함께 고칩니다.
5. prompt, AI 응답, 코드, diff, 파일 경로를 수집하거나 로그에 남기지 않습니다.

문제가 생기면 [장애 대응 가이드](./장애_대응_가이드.md)를 확인하세요.
