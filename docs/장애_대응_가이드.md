# 장애 대응 가이드

## 먼저 할 일

1. 신규 배포와 파일럿 사용자 확대를 멈춥니다.
2. 발생 시각, 환경, service version, request ID를 기록합니다.
3. liveness와 readiness를 각각 확인합니다.
4. body, cookie, token, prompt, 코드, 경로를 수집하지 않습니다.
5. 치명적 사고라면 관련 kill switch를 적용합니다.

```text
GET /api/v1/health/live
GET /api/v1/health/ready
GET /api/v1/health/metrics   # 운영 bearer token 필요
```

## 증상별 대응

| 증상 | 우선 확인 | 첫 대응 |
|---|---|---|
| liveness 실패 | process·container 상태 | API instance 재기동 |
| readiness 실패 | DB 연결·pending migration | traffic 제외, migration 상태 확인 |
| 5xx 증가 | route template·error code·request ID | 최근 배포 중단, 필요 시 app rollback |
| 로그인 실패 | OAuth App·callback·secret·proxy hop | 신규 로그인만 중단하고 설정 확인 |
| 자동 감지 누락 | device lastSeen, queue age, heartbeat 만료 | 수동 session 안내, event switch 확인 |
| queue 적체 | queue depth·oldest age·dead-letter | 서버 5xx/429/인증 상태부터 확인 |
| 포인트 이상 | attempt·ledger unique constraint | 제출 중단 switch 적용 |

## Kill switch

| 설정 | 결과 |
|---|---|
| `INTEGRATION_EVENTS_ENABLED=false` | event에 재시도 가능한 `503`과 `Retry-After: 60` 반환; plugin queue 보존 |
| `QUEST_REWARDS_ENABLED=false` | 채점 transaction 전에 제출 차단; 포인트 없는 통과 방지 |

값 변경 후 API를 재기동하고 readiness를 확인합니다.

## 즉시 파일럿을 중단하는 사고

아래 항목은 한 건만 발생해도 신규 초대를 중단합니다.

- prompt, AI 응답, 코드, 경로 등 금지 데이터 노출
- 다른 사용자의 데이터 접근 또는 권한 우회
- 실제 중복 포인트 적립
- 복구할 수 없는 session 또는 사용자 데이터 유실

## 종료 조건

- 원인이 확인되고 수정 또는 완화됨
- readiness와 smoke가 정상
- 5xx와 queue 지표가 안정 구간으로 복귀
- 중복 보상·데이터 유실·개인정보 노출 여부 확인
- incident 기록과 재발 방지 작업 등록

상세 alert별 명령, backup 복원, secret 회전 절차는 [`ai/OPERATIONS_RUNBOOK.md`](./ai/OPERATIONS_RUNBOOK.md)를 확인하세요.
